================================================================================
  ABLATION STUDY: Screenshot (Vision) vs ASCII Grid State Representation
================================================================================

Overview
--------
This ablation compares two ways of conveying game state to the LLM:

  1. SCREENSHOT (baseline) – Rendered PNG screenshots of the HTML5 canvas are
     base64-encoded and sent as multimodal image inputs.  The LLM must visually
     interpret pixel-level game state.

  2. ASCII GRID (experimental) – The VGDL engine's symbolic game state is
     extracted via `game.getFullState()`, converted to a 2-D character grid
     with a legend, and sent as plain text.  No vision tokens are used.

Both modes share the same action interface (up to 10 keys per LLM call),
the same Selenium-based JS game engine, and the same conversation / summary
management logic.  Only the state representation and prompt wording differ.

Usage
-----
  # Baseline (screenshot / vision)
  python llm_gameplay.py --model openai:gpt-5.2 --url <game_url> --max_actions 400

  # Experimental (ASCII grid)
  python llm_gameplay.py --model openai:gpt-5.2 --url <game_url> --max_actions 400 \
      --state_representation ascii

================================================================================
  ANALYSIS
================================================================================

  1. ASCII mode achieved MORE total wins (5 vs 2) across the same 9 games.

  2. ASCII mode won in 4 unique games vs 2 for screenshot mode, unlocking
     wins in chase and bait that screenshot mode never achieved.

  3. Screenshot mode had an edge in butterflies (won 1, max score 28) where
     ASCII scored only 6 and never won — likely because butterfly movement
     patterns are easier to track visually than via grid symbols.

  4. In aliens, ASCII achieved a higher max score (19 vs 17) despite neither
     mode winning, suggesting better spatial reasoning for shooting games.

  5. Frogs remains unsolved in both modes — the game's tight timing
     requirements exceed the 10-actions-per-call granularity.

  6. ASCII mode generated far more episode endings (42 vs 24), indicating
     more aggressive/decisive play rather than aimless exploration.

================================================================================
  HYPOTHESES & OUTCOMES
================================================================================

  H1: ASCII mode will IMPROVE win rate because the LLM receives exact,
      unambiguous positional information rather than having to interpret
      pixel-level screenshots.
      RESULT: SUPPORTED. Win rate increased from 8.3% to 11.9%, and ASCII
      unlocked wins in 2 new games (chase, bait) that screenshot never won.

  H2: ASCII mode will REDUCE token cost significantly by eliminating
      vision/image tokens.
      RESULT: SUPPORTED (qualitatively). ASCII sends ~200-500 text tokens per
      state vs thousands of vision tokens per screenshot.

  H3: ASCII mode may HURT performance on games where visual cues (color,
      animation direction, sprite appearance) carry information not captured
      by the single-character symbol mapping.
      RESULT: PARTIALLY SUPPORTED. Butterflies went from 1 win / max 28 score
      (screenshot) to 0 wins / max 6 score (ASCII).


================================================================================
  IMPLEMENTATION NOTES
================================================================================

  Files changed:
    - utils/game_utils.py        Added get_game_state_matrix(), get_game_dimensions(),
                                 _symbol_for_sprite(), SPRITE_SYMBOL_MAP
    - llm_gameplay.py            Added --state_representation flag (screenshot|ascii),
                                 append_ascii_state() helper, conditional logic in
                                 main loop for state capture, frame history, and
                                 visual section building
    - prompts/ascii/*.md         ASCII-specific prompt variants (6 files) that
                                 reference "ASCII grid" instead of "image"

  ASCII grid format example:
    Legend: A=avatar W=wall E=enemy G=goal .=empty
    WWWWWWWW
    W..A...W
    W..E.G.W
    WWWWWWWW

  Symbol assignment priority:
    1. Walk the sprite's stypes list (most-specific first) against SPRITE_SYMBOL_MAP
    2. Fall back to the sprite group key
    3. Last resort: first letter of the type name, uppercased
    Avatar ("A") always takes priority when sharing a cell with another sprite.
